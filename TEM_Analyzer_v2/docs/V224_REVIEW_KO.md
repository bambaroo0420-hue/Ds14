# v2.2.4 — 독립 ROI 분할·후보 선택·crop 절단 경계 보호

2026-09-30 KST, 5시간 반복 개선 중 5차 기록. 회사 영상/전문가 물질 GT는 없으며 완전 자동 분석이 완성된 것은 아닙니다.

## 사용자 의도와 이번 개선

- 기존에는 ROI 재분할에 부모 마스크가 필요했습니다. 이제 **2 SAM·레이어 → 부모 없이 ROI 확대 분할**에서 노란 추론 ROI를 드래그하고 양성/음성점 또는 SAM box를 지정할 수 있습니다.
- 추론 ROI는 입력 영상을 잘라 SAM에 확대 입력하는 범위이고, SAM box는 객체 힌트입니다. 서로 다릅니다. 결과 좌표는 원본 픽셀로 복원하고 ROI 밖을 채우지 않습니다.
- 기본 SAM의 3개 후보를 각각 미리보고 선택할 수 있습니다. 자동은 기존 최고 예측점수입니다. 후보 번호를 바꾸면 이전 미리보기를 저장할 수 없으며 재실행해야 합니다. 동일 ROI 영상이면 embedding을 재사용합니다.
- 미리보기는 후보 파일을 만들지 않습니다. `확인 후 새 후보 저장`만 미배정 후보를 추가합니다. 레이어 배정은 나중에 하거나, 이 마스크만 선택 집합에 넣어 GT 없이 회전·계측할 수 있습니다.
- 양성/음성점과 결과가 맞지 않는 개수, ROI 절단 의심 경고를 표시합니다. 이는 QC 경고이지 자동 물질 판정이나 GT 인증이 아닙니다. 학습 single-mask/이전 mask 입력 경로에서 없는 후보 번호는 명시적으로 거절합니다.

## 실제 SAM 비교: 잘 된 것과 실패한 것

동일한 수동 보조 점으로 전체 영상과 ROI를 비교했습니다. 새 모델은 설치하지 않았습니다. 기본 SAM ViT-B CPU입니다.

| 생성 영상: 3px 두께 띠 | 전체 영상, ROI 내부 IoU | ROI 확대, ROI 내부 IoU |
|---|---:|---:|
| 0° | 0.05547 | 0.75188 |
| 30° | 0.04457 | 0.64392 |
| 45° | 0.04474 | 0.66667 |

원본 1536×512에서 300×360 관심영역을 사용했습니다. 표는 **crop 내부 정답**만 비교합니다. ROI 밖 복구, 자동 점 선택, 회사 물질 분류 성능이 아닙니다. 세 합성 영상에서는 최고 점수 후보가 후보 3이었으나 일반 법칙이 아닙니다.

첨부 TEM는 ROI만으로 해결되지 않았습니다. TaOx·TiOxNy 두 보조 사례 모두 세 후보가 음성점 2개를 위반했고 넓은 잘못된 영역을 포함했습니다. 최고 점수가 약 0.994/0.990이어도 올바른 물질 경계가 아니었습니다. TiOxNy 후보 3은 경계각 약 −44.38°로 그럴듯하지만 오버레이에서는 이웃층까지 넓게 포함합니다. **각도 일치만으로 성공으로 계산하지 않았습니다.**

공개 140 영상의 세 후보 면적은 6581/5763/5009px로 달랐습니다. 전문가 GT가 없어 우열을 확정하지 않습니다. hafnia h는 기존 OCR 제외 후 유효 양성점이 1개뿐이고 한 후보는 그 점도 위반했습니다. 기존 과대 제외/단일점 모호성도 남아 있습니다.

실제 호출 구분:

- 전체/ROI 7사례×2 = 14회, cold encoder, 추론 시간 합 191.555초.
- 같은 7 ROI의 후보 3개 비교 = decoder 예측 21회, cold encoder 7회 + embedding 재사용 14회, 합 95.816초.
- 실제 GUI에서 후보 3→1→3 비교 = 3회 추가. 마지막 2회는 동일 crop embedding 재사용.
- 이번 반복 총 **38회 예측**입니다. 모두 독립 cold 추론 38회라고 표현하지 않습니다.

증거: `test-output/roi-compare-v224/results.json`, `roi-alternatives-v224/results.json` 및 원본 위 후보 오버레이. 자료는 로컬만 보존하고 GitHub에는 올리지 않습니다.

## crop의 가짜 경계를 GT·계측에서 보호

`candidate.inference_domains`에 원본 좌표의 반열린 추론 ROI `[x0,y0,x1,y1]`를 보존합니다. 내부 crop 가장자리에서 2px 이내에 있는 마스크 픽셀을 절단 의심으로 보고 2px 더 확장해 unknown 처리합니다. 초기 실제 시험에서 45° 출력이 crop 끝보다 1~2px 안쪽에서 멈추는 반례가 있어 정확히 끝에 닿는 경우만 보던 검사를 보완했습니다.

- 원본과 저장 mask 픽셀은 변경하지 않습니다. GT/계측 validity와 자동 경계/대표점 회전 fit에서 보호합니다. 레이어 공유 Gradient+DP도 이 영역을 변경하지 않습니다.
- 전체 이미지 프레임은 별도의 기존 프레임 정책입니다. 자연 경계가 crop 가까이에 있어도 보수적으로 보류할 수 있으므로 ROI를 넓혀 재검토하세요. 2px보다 멀리서 생긴 SAM 가짜 끝점을 모두 탐지하는 장치는 아닙니다.
- ROI 밖을 보존한 부모 편집에는 새 crop 절단 provenance를 붙이지 않습니다. crop 후보 복제/브러시/자식은 기존 provenance를 유지합니다.
- cut 영역을 통과하는 CD/두께는 `invalid_region`, 확정 길이는 빈 값이며 `raw_length_nm`와 이유를 남깁니다. 직접 지정 기준점은 사용자 판단 경로로 유지하고 경고합니다.
- ROI 결과를 사용하는 기존 회전/측정은 버전 hash 변경으로 재검토합니다. ROI가 없는 기존 데이터 hash는 유지합니다.

## 실제 선택 마스크 일괄 GT·계측

기존 실제 SAM 결과의 후보 3만 선택한 합성 3장(0/30/45°)에서 레이어를 하나도 배정하지 않았습니다. 회전 3/3 → 확인 → 미검수 계측 3/3 → 워크플로 검수 → 부분 GT+계측 6/6 → ZIP을 검증했습니다. 부분 GT의 crop 의심 영역과 미선택 영역은 모두 unknown입니다. 이는 워크플로 확인이지 전문가 검수가 아닙니다.

| 정답 방향 | 자동 경계 방향 | 평균 두께(px) | 중앙값(px) | 생성 띠 폭 |
|---|---:|---:|---:|---:|
| 0° | 0.00000° | 4.0000 | 4.0000 | 3px |
| 30° | 29.92407° | 3.3321 | 4.1122 | 3px |
| 45° | 44.61723° | 4.1612 | 4.9499 | 3px |

**ROI로 IoU가 개선되어도 얇은 층 두께는 과대·분절 오차가 남았습니다.** 1nm/px는 생성 영상 시험용 가정이며 실제 TEM 축척이 아닙니다. 평균이 3에 가까운 30° 결과도 작은 분절 표본이 포함돼 정확도 성공으로 보지 않습니다. 실제 회사 적용에는 경계 보정/검수, 원본 해상도, 최소 분해능 기준이 필요합니다.

첫 검증 도구는 모든 crop이 정확히 가장자리에 닿는다고 가정해 중단됐습니다. 원인 분석 후 near-edge 보호를 추가하고 새 폴더 `test-output/roi-metrology-v224-final`에서 완료했습니다. 실패 실행을 별도 성공으로 세지 않습니다. 선택 밖에 남긴 다른 두 후보도 보존·미배정입니다.

## GUI와 회귀

독립 테스트 프로젝트 `test-output/roi-ui-v224`, 포트 8886에서 실제 마우스로 ROI를 드래그하고 +3/−2점을 추가했습니다. 후보 변경 시 저장 비활성, 재미리보기, 저장 후 3→4개 후보, 부모 없음/미배정, 후보 #22만 선택 scope 저장, GT 없이 회전·계측을 확인했습니다. 알려진 30° 입력의 GUI 추정은 29.95847°였고 보정 후 수평을 화면으로 확인했습니다. 이 GUI의 ROI/점은 자동 비교 도구와 조금 다르므로 수치를 혼합하지 않습니다.

새 경계 보호의 단위/API 검증에는 10px 온전한 내부 두께 성공, crop에 의해 잘린 40px CD 거절, 사각형 crop의 가짜 0° 회전 차단, 수동 제외 영역의 점 거절, 제외 변경 후 preview 저장 차단, provenance 상속이 포함됩니다. 전체 테스트 및 게시 결과는 `ITERATION_VNEXT_KO.md`의 v2.2.4 최종 항목을 참조하세요.

최종 staging Python116개 21.895초, 기존+재사용 Node UI 테스트, pip check 통과. 실제 GUI 서버를 최종 near-edge 규칙으로 재시작한 뒤 기존 회전/계측 만료 안내 → 재회전/확정/계측도 확인했습니다. #22의 최종 잠정 평균3.5496/중앙4.3932nm, 유효19/무효21개(교차 없음125), cut 보호145px입니다. GUI는 생성1nm/px를 직접 입력한 시험이며 분할 정확도 인증이 아닙니다.

## 남은 자동화 과제

1. 독립 ROI는 현재 대화형 기능입니다. ROI 레시피를 여러 영상에 자동 이동·확정하는 일괄 기능은 아직 없습니다. 기존 Grid/feature/Grid+feature와 검수된 preset의 일괄 SAM은 유지됩니다.
2. 첨부 논문 이미지의 색선·화살표·이미 지워진 질감은 입력 경계 정보를 훼손합니다. 높은 점수로 자동 후보/GT 확정하지 않습니다. 사전 방향 정렬+제한 box, 원본 고해상도, 적합한 학습 데이터 비교가 다음 후보입니다.
3. crop 버전과 full 버전 사이의 overlap 병합·물질 ID 대응은 미구현입니다. 선택 scope는 물질 레이블이 아닌 binary 합집합입니다.
4. 실제 사용자 검수 없이 모든 후보가 자동 GT가 되는 기능은 의도적으로 제공하지 않습니다. 회사 영상과 전문가 기준으로 별도 정확도 검수가 필요합니다.

## 참고와 구현 범위

[공식 SAM 자동 마스크 코드](https://github.com/facebookresearch/segment-anything/blob/main/segment_anything/automatic_mask_generator.py)의 crop 경계 필터와 point-grid 경로를 확인했습니다. 본 도구는 사용자 ROI를 기존 predictor에 전달하며 공식 automatic generator의 전역 `crop_n_layers`를 켠 것은 아닙니다. [μSAM 분할 문서](https://computational-cell-analytics.github.io/micro-sam/micro_sam/instance_segmentation.html)는 별도 microscopy 전략 참고이며 μSAM 모델을 설치·검증했다는 뜻이 아닙니다.

새 의존 패키지는 없습니다. 변경 책임: `sam_service.py`(기본 후보 선택/QC), `roi_review.py`(저장 전 검수), `roi_domains.py`(crop provenance/validity), `labels.py`·`services/scopes.py`·`services/measurement.py`·`services/layers.py`(GT/회전/계측/DP 보호), `web/roi_editor.js`(독립 ROI UI). 재현 도구는 `tools/compare_roi_prompts.py`, `compare_roi_alternatives.py`, `validate_roi_metrology.py`입니다.
