# 공개 TEM 이미지 기반 구현 적합성 검토

검토일: 2026-09-30. 대상: TEM Analyzer v2.1 + 선택형 추가점/노이즈 제거 기능.

## 결론

**사용자가 검수하는 반자동 도구로는 방향이 맞지만, 여러 TEM 이미지에서 자동으로 완성된 GT와 신뢰할 만한 두께/CD를 만드는 수준은 아직 아닙니다.**

분할 → 레이어 배정 → 선택적 경계 보정/GT → 회전 → 계측의 분리는 적절합니다. 실제 화면에서 분할만 일괄 실행하고, 나중에 레이어를 배정하는 흐름도 작동했습니다. 그러나 자동 문자 제외·축척 인식·얇은 층 선택·회전 기준 선택은 공개 이미지의 변화에 충분히 강건하지 않았습니다. 버튼 성공을 분석 성공으로 판단하면 안 됩니다.

이번 검토에서 발견한 OCR·회전의 기존 한계는 임의로 광범위하게 수정하지 않았습니다. 요청한 추가점/노이즈 제거 기능은 구현했고, 나머지 보완안은 아래 우선순위로 제안합니다.

## 1. 무엇을 실제 실행했는가

| 구분 | 실행 범위 | 확인한 것 | 확인하지 못한 것 |
|---|---|---|---|
| Python 회귀 | 63개 테스트 통과 | API, 제외 영역, 좌표, 필터, 배치, 회전/계측 및 기존 기능 | 현장 정확도 |
| UI 코드 회귀 | Node 테스트 통과 | 실제 핸들러 + 모의 DOM/Canvas | 전체 브라우저 동작과 동등하지 않음 |
| 실제 브라우저 | 별도 로컬 테스트 프로젝트, 공개 이미지 2장 업로드 | 이미지 선택, Canny+Median 미리보기/추가, 실제 SAM 모델 로드/분할, Sobel+NLM 미리보기, 2장 일괄 SAM, 이후 레이어 배정, SAM용 NLM 저장/미리보기 | 모든 OS/브라우저·파라미터 조합 |
| 실제 영상처리 | 기존 10장 + 신규 4장, 총 14장 × 5방식 × 5필터 = 350회 | 예외 없이 제안 완료, 점 위치/수량/시간 기록 | 제안점의 의미적 정답률 |
| 실제 SAM | 14장 × K-means/Canny/Sobel = 42회 | 로컬 ViT-B CPU로 실제 마스크 생성·저장 | GT IoU/Dice, 최종 두께/CD 정확도 |
| 실제 OCR | 위 14장 전체, 로컬 EasyOCR | 문자/바 박스, 축척 제안과 실패 기록 | 장비별 검출률 추정 |
| 첨부 45° 이미지 | 별도 실제 OCR/SAM·회전 비교 | 실패와 수동 보조 대안 분리 | 자동 문자 완전 제거·자동 수평 보정 성공 아님 |

추가 공개 이미지의 다운로드는 읽기 전용 수집입니다. 학습, 외부 추론 업로드는 하지 않았습니다. 원본·가중치·테스트 프로젝트·첨부 이미지는 GitHub 소스에 포함하지 않습니다.

## 3. 테스트 조건과 수치

- SAM: 실제 로컬 ViT-B, CPU, 학습 decoder/refiner 미사용. 가중치 SHA-256 `ec2df62732614e57411cdcf32a23ffdf28910380d03139ee0f4fcbe91eb8c912`.
- 추가점: 최대 12점, 최소 간격 12px, 에지 이격 3px, Canny 40/100, Sobel/Scharr 백분위 75. 나머지 기본값.
- 필터 조합: 없음, Gaussian, Median, Bilateral, Non-local Means. 프롬프트 분석은 긴 변 최대 512px.
- SAM 비교 42회는 **추가점 분석에만 Median 3**, SAM 입력에는 별도 denoise를 적용하지 않았습니다. Predicted IoU 0.5 / Stability 0.7 / NMS 0.8로 후보 관찰을 위한 완화 조건입니다. 앱 기본 0.90/0.92에서 같은 수량이 나온다는 뜻이 아닙니다.
- 자동 OCR 제안은 이 감사용 프로젝트에서 그대로 제외하여 후속 영향을 관찰했습니다. **잘못 제안된 제외 박스의 영향까지 포함**된 결과입니다. 사용자가 정상 검수한 상태의 최선 성능과 구분해야 합니다.

**후보 수가 많거나 이미지 전체를 덮는다고 좋은 분할은 아닙니다.** 42회 모두 마스크는 나왔지만 배경·텍스트·스케일바·삽입 도표 후보도 섞였습니다. 수치 3/14는 자동 축척 **제안 발생 수**일 뿐 정확한 스케일 검출률이 아닙니다. 독립적으로 검수한 정답 바 길이 데이터셋이 없으므로 정확도를 계산하지 않았습니다.

350회 프롬프트 생성은 이 PC에서 평균 약 0.218초, 최대 약 0.859초였습니다. 설정별 품질·속도 우열을 확정하는 벤치마크는 아닙니다. SAM 실행은 매 이미지에서 K-means를 먼저 실행해 첫 인코딩 비용을 부담하고 Canny/Sobel은 동일 이미지 임베딩을 재사용했습니다. 따라서 기록된 SAM 시간을 그대로 비교해 “Canny가 몇 배 빠르다”고 주장하면 잘못입니다.

## 4. 육안 검토에서 발견한 장단점

| 항목 | 장점 | 관찰한 한계/위험 |
|---|---|---|
| K-means | 밝기·질감이 다른 작은 영역까지 비교적 다양한 후보 | 물질 분류가 아니며 글자/도표/밝은 바도 후보가 됨. 158처럼 저대비 층은 합쳐짐 |
| Canny/Sobel | 큰 영역 내부에 점을 놓아 경계 위 클릭을 줄임 | 거리변환 최대점을 우선하므로 넓은 배경·기판을 선호. 55/76에서 작은 반복 셀을 충분히 고르지 못함 |
| Scharr/혼합 | 선택지와 비교 미리보기 제공, 350회 조합 검증 포함 | 실제 SAM 42회 비교에는 포함하지 않음. 우수성을 검증했다고 주장할 수 없음 |
| 노이즈 제거 | 원본 불변, 프롬프트용/SAM용 분리, 끄기 가능 | 얇은 층·원자 대비를 소거할 수 있음. 한 필터가 모든 이미지에서 유리하지 않음 |
| OCR 제외 | 박스별 검토 후 적용 가능, 자동 확정 안 함 | 76에서 구조 대부분을 큰 `FE` 문자 박스로 오인. 이 박스를 적용하면 유효 분석 영역 자체가 훼손됨 |
| 스케일 | 문자와 실제 바를 연결, 복수 후보 표시 | 작은 바·OCR 여백·두께 화살표/장치 경계 혼동. 157에는 50nm 바 외 28.5nm 주석/층 경계 후보도 존재 |
| SAM | 로컬 실제 모델로 여러 후보 생성, 나중에 편집/배정 가능 | 얇은 층은 누락/병합, 미세입자는 매우 부족. 후보 점 수를 늘리는 것만으로 해결 안 됨 |
| 레이어/GT | 배정·검수 구분, unknown 유지, 겹침 검사 | 자동 물질명 분류·완전한 instance 대응·전체 위상 해결은 없음 |
| 회전 | GT 없이 레이어로 계산, 원본↔회전 좌표 변환 | 잘못된 마스크/영상 테두리를 기준으로 잡으면 잔차가 작아도 각도가 틀릴 수 있음 |
| 계측 | 회전 후 방향·구간 지정, 제외/충돌 구간 무효 처리 | 마스크·스케일 오류를 물리값에 그대로 전파. 이번 14장에는 정답 두께/CD가 없어 정확도 미검증 |

논문 그림에 이미 그려진 화살표·점선·색 선은 OCR 문자가 아닙니다. “문자 박스 제외”만으로 이러한 주석까지 전부 제거되지는 않습니다. 박스 안을 주변 유효 픽셀로 채우는 것은 **추론용 대체 입력**이며 실제 재료 조직의 복원이 아닙니다. 채운 픽셀은 GT/계측에서 계속 제외되어야 합니다.

## 6. 사용자 의도와 구현의 일치도

| 요구 | 판단 |
|---|---|
| 여러 비슷한 이미지 먼저 분할, 나중에 레이어 정리 | 일치. 실제 2장 SAM-only 배치 완료 후 별도 배정 확인 |
| 같은 SAM 점·box를 다른 이미지에 재사용 | 아직 없음. 현재는 동일 추가점 설정으로 이미지마다 다시 생성함 |
| SAM 화면에서 이미지 선택 | 이번 수정에서 전용 선택 목록과 후보/미배정 수 추가 |
| 외곽 부근 Gradient+DP 보정 | 구현되어 있으나 임의의 물질 경계를 자동으로 아는 기능은 아님 |
| GT 없이 회전/계측 | 일치. 마스크 기반 경로와 잠정값 구분 존재 |
| 모든 문자/바를 자동 제외 | 부분 일치. 논문 주석과 촬영 메타데이터 구분 필요 |
| 정확한 일괄 GT/물리 계측 | 준비 단계. 회사 이미지/전문가 GT 검증 전 자동 승인 금지 권고 |

## 8. 결과 파일과 재현
