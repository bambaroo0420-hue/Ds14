# v2.2.7 — 회전 기준 비교와 일괄 실패 격리

2026-09-30 KST. v2.2.6의 보존된 실제 SAM 출력 5개를 사용했습니다. 신규 SAM 추론 0회이며 회사 영상/전문가 GT는 없습니다.

## 목적과 구현

자동 경계가 약 41°로 흔들린 첨부 사례에서, 어느 기준이 잘못됐는지 확인할 수 있도록 `4 회전·계측 → 회전 기준 비교 (자동 확정 안 함)`을 추가했습니다.

- 현재 설정, 자동 위/아래 경계, 영상 주 방향, 단일 mask의 저장된 SAM 양성점 방향, 입력한 대응점을 비교합니다. 동일 설정은 중복 표시하지 않습니다.
- 각도·잔차·점 수·경고/실패를 표시합니다. 영상 주 방향에 붙인 두 가상 끝점을 실제 표본 두 개로 표시하지 않습니다.
- 비교 요청 자체는 회전·계측·GT·revision·Undo 이력을 바꾸지 않습니다. 후보별 실패는 다른 기준의 결과를 막지 않습니다. 선택 집합 자체가 없으면 전체 요청이 실패하며 레이어로 대체하지 않습니다.
- `이 기준으로 미리보기`는 별도 회전 제안을 저장하고 기존 계측을 만료시킬 수 있습니다. **자동 확정하지 않습니다.** 선택 후 원본/회전 화면을 확인하고 별도로 확정해야 합니다.
- 잔차 최솟값이나 45° 근접값을 자동 선택하지 않습니다. SAM 양성점은 대개 사람이 배치한 물질 내부 점이지 전문가가 검수한 경계점이 아닙니다.

## 보존된 실제 mask 비교

`tools/compare_rotation_references.py`로 4영상·5후보 × 전체/고정 내부 ROI × 4기준 = 40방향 제안을 비교했습니다. 새로운 SAM 예측이나 mask 변경은 없습니다. 아래는 전체 구간의 **보정각**입니다. 영상 좌표에서 시계 방향이 양수이며 수평 목표0° 기준입니다.

| 영상/후보 | 자동 위쪽 | 자동 아래쪽 | 영상 주 방향 | 저장 SAM 양성점 |
|---|---:|---:|---:|---:|
| 생성 45° / 1 | −45.0000° | −45.0000° | −45.0000° | −45.0000° |
| 첨부 TaOx / 2 | 44.9181° | 18.0952° | 44.1441° | 44.9953° |
| 첨부 TaOx / 5 | 41.1896° | −0.9381° | 44.1441° | 44.9961° |
| 첨부 TiOxNy / 3 | 46.9182° | 48.6541° | 44.1441° | 45.0000° |
| 공개 140 / 4 | 3.0610° | 2.3600° | 1.6643° | 2.2270° |

TaOx 후보5의 위/아래 경계 잔차는 6.9715/17.6842px, 저장 양성점은 0.4263px입니다. 양성점 방향이 약45°라는 사실은 경계 분할이 정확하다는 뜻이 아닙니다. 후보2의 위쪽 잔차0.8664px가 작아도 아래쪽은 약18°로 불일치합니다.

고정 내부 ROI `[0.3,0.1,0.6,0.9]`에서 첨부의 영상 방향은 **88.4171°**로 실패했고, TaOx 후보5의 위/아래는 39.1477/59.9526°였습니다. 이 ROI는 비교용 고정 영상좌표이지 좋은 구간으로 찾아낸 값이 아닙니다. 좁은 ROI가 항상 낫다는 가정을 하지 않습니다. 생성 띠와 공개140의 내부 구간은 비교적 일관됐지만 실제 TEM 정확도 평가가 아닙니다.

## 일괄 처리 수정과 실제 경로

이전 구현은 한 영상의 단계가 실패하면 이후 단계 실행을 중단했지만, 건너뛴 단계에 대한 행이 없어 종료 후 `done/total`이 맞지 않을 수 있었습니다.

이제 후속 단계마다 `status=skipped`, `blocked_by=<실패 단계>`, 설명을 기록합니다. 처리 수에는 성공·실패·건너뜀이 포함되며 UI는 각 개수를 구분합니다. **8/8은 8개 성공이라는 의미가 아닙니다.** 취소·중단의 미시작 작업은 완료 수로 올리지 않습니다.

- API 실제 프로젝트: 4장·선택 mask만·GT→계측. GT 미검수4 실패 + 후속 계측4 건너뜀 = 처리8/8.
- 생성 영상 한 장만 프로그램 검사 목적으로 검수·회전·1nm/px를 확정하고 실제 retry API 호출: 성공2 + 실패3 + 건너뜀3 = 처리8/8. 나머지 실제 TEM에는 가짜 축척이나 GT 확정을 부여하지 않았습니다.
- 생성 영상의 선택부분 GT ZIP: unknown784,506px, valid1,926px. 후보5개 모두 보존·레이어미배정. 선택 밖을 배경으로 자동 라벨링하지 않았습니다.
- 이 생성 SAM mask의 3px 참값 대비 평균은 **4.6898px**, 중앙값4.9497px(간격3px), 유효137/무효4. 파이프라인 성공과 경계·두께 과대 오차를 구분해야 합니다.

## 코드 책임과 남은 한계

- `services/measurement.compare_alignment`: 고정된 비교 후보 생성과 순수 제안, 자동 채택 없음.
- `/api/workflow/rotation/compare`: 거래 이력 제외·프로젝트 gate 유지. 비교는 읽기만 하며 추론/계측을 실행하지 않음.
- `web/modules/rotation_compare.js`: 표·선택·stale 응답/선택 방지. 선택 시 기존 preview API 사용.
- `jobs/manager.py`: 실패한 영상의 후속 단계만 skipped 기록. retry는 기존 failed행 기준이며 이미 성공한 이전 단계를 재실행하지 않음.
- `web/modules/batch.js`: 성공/실패/건너뜀을 구분하고 회전의 잔차/미확정 상태도 표시.

사용자 의도인 ‘GT 없이 회전·계측’과 ‘특정 mask만 선택한 부분 GT’는 유지됩니다. 다만 경계 분절·누출과 얇은 층 두께 과대 오차는 남았습니다. 여러 기준의 합의는 재료 경계 GT의 대체물이 아닙니다. 생성 데이터에서 −45°가 맞더라도 실제 이미지에서 자동 확정을 허용하는 근거가 되지 않습니다. 최종 회사 데이터의 전문가 검수와 촬영 조건별 정량 평가가 필요합니다.
