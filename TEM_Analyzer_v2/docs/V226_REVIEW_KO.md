# v2.2.6 — 방향 보조 ROI 분할 및 회전 비교창 검증

검증일: 2026-09-30 KST. 회사 영상/전문가 물질 GT 없음. 실제 모델은 기존 SAM ViT-B, CPU이며 새 모델/패키지를 설치하지 않았습니다.

## 결론

양성점으로 직선층 방향을 정해 ROI만 사전정렬하고, 선택적으로 좁은 box를 주는 방식은 일부 과대 분할을 줄였습니다. 그러나 첨부 TiOxNy의 분절과 불완전 경계는 해결되지 않았습니다. GUI에서 조금 다른 ROI/점을 지정하자 TaOx의 최종 회전이 41.1896°로 흔들렸습니다. 따라서 **기본 꺼짐인 실험 옵션**, 저장 전 후보 검토, 회전 미확정 상태를 유지합니다. 자동 GT 완성이나 회사 계측 정확도 확보를 의미하지 않습니다.

## 사용법과 범위

1. `2 SAM·레이어`에서 이미지를 선택하고 `부모 없이 ROI 확대 분할`을 엽니다. 부모 mask가 필요 없습니다.
2. 관심 층을 포함하는 ROI와 같은 직선층을 따라 양성점 2개 이상을 지정합니다. 이웃 층에는 음성점을 추가할 수 있습니다.
3. `양성점 방향으로 ROI 사전정렬`을 켜면 점의 robust line으로 입력 ROI를 정렬합니다. 너무 휘거나 방향성이 약한 점 배열은 오류로 돌려줍니다.
4. box 여백은 법선 방향 픽셀입니다. 0이면 자동 box 없음, 6/18 등은 비교에 사용한 예시일 뿐 일반 최적값이나 물리 두께가 아닙니다. 길이 방향 여백은 30px입니다. 수동 box와 자동 box는 동시에 사용할 수 없습니다.
5. 후보 1/2/3을 비교하고 저장합니다. 후보는 원본 좌표로 복원되고 레이어 미배정 상태입니다. 옵션/점 변경 시 이전 미리보기의 저장 버튼이 비활성화됩니다.
6. 필요한 mask만 분석 대상으로 선택하고 별도로 회전을 제안·검토합니다. GT 생성은 회전/계측의 선행 조건이 아닙니다.

이 기능은 독립 ROI 단일 영상 경로입니다. 부모/seed 편집이나 저장된 ROI 레시피의 영상 간 일괄 재사용은 아직 지원하지 않습니다. 기존 프롬프트 preset 일괄 기능과 구분해야 합니다. 점·ROI 선택은 사람이 보조한 실험이며 완전 자동화 시험이 아닙니다.

## 실제 SAM 비교

`tools/compare_oriented_roi.py`: 6사례 × 4방식 × 3후보 = 72예측. 11 cold + 61 embedding reuse, 기록된 추론 시간 합계 162.5213초. 회전된 입력마다 embedding은 별개이며 동일 입력의 box/후보 변경은 재사용됩니다.

- 사례: 생성 3px 띠 0/30/45°, 첨부 TaOx/TiOxNy, 기존 공개 140 영상.
- 방식: native box, 사전정렬+점만, 사전정렬+box 여백6, 사전정렬+box 여백18.
- 추가 공개 hafnia는 기존 OCR 제외 후 양성점이 1개뿐이라 사전정렬 조건을 충족하지 못해 건너뛰었습니다. 실행 당시 마지막 skip의 JSON 저장 누락을 발견해 도구를 수정했습니다. 기존 결과 JSON은 72개 실측 행이며 skip 행은 없습니다. 이 문서에 별도 기록하며 72회 추론을 중복하지 않았습니다.

## 첨부 영상과 실제 API·GUI

- TaOx: box18 후보1은 면적 29,299px, 지정 점 위반 0. 기존 전체 ROI를 포함하던 후보보다 국소화됐지만 누출과 경계 오차가 남습니다. 최종 서비스의 central edge fit은 약 −44.9181°, 잔차 0.8664px였습니다. 물질 정답 검증은 아닙니다.
- TiOxNy: box6 후보3은 면적 9,653px, 지정 점 위반 0이지만 분절/누락이 보입니다. 서비스 fit은 약 −46.9182°, 잔차 6.114px로 검토가 필요합니다. 음성점 준수나 45° 근접만으로 성공 처리하지 않았습니다.
- `tools/validate_oriented_roi_api.py`: 생성45°/TaOx/TiOxNy/공개140의 최종 API 실제 SAM 4 cold 예측, 57.8563초. preview → accept → 선택 scope → rotation preview 경로가 실행됐고 실험 도구의 대응 mask와 IoU 1.0. 모든 후보 미배정이며 GT/스케일/회전 자동 확정을 하지 않았습니다.
- 실제 GUI 추가 2예측(1 cold + 1 embedding reuse): ROI 드래그, +3/−2점, 사전정렬, box18, 미리보기 → 여백6으로 변경하면 이전 저장 불가 → 18 재예측 → 새 후보5 저장 확인. 기존 후보는 유지됐습니다.
- GUI에서 ROI `[70,131,428,467]`로 생성한 TaOx 후보5는 면적 22,929px, 점 위반0, SAM score 약0.925였습니다. 이 후보만 선택한 최종 자동 회전은 **41.1896°, 잔차6.97px**로, 잘못된 경계가 회전까지 전파되는 반례입니다. `회전 검토 필요`로 남겼으며 확정하지 않았습니다.
- 합계 **78 실제 SAM 예측(16 cold, 62 reuse)**. 모형/코드 단위 테스트를 실제 모델 실행 수에 합산하지 않았습니다.
- 이 비교창은 원본 주석을 보존해 표시합니다. 문자 삭제·자동 OCR 정확도를 새롭게 검증한 실험이 아니며, 주석이 보인다는 이유로 제외 마스크 적용과 원본 파일 보존을 혼동하면 안 됩니다.

## 비교창 로딩 보완

양쪽 이미지를 load/decode하고 실제 크기를 확인한 뒤 비교창을 엽니다. 실패/15초 timeout은 재시도 안내를 보여주며 늦은 완료가 실패를 덮지 못합니다. 대기 중 선택 영상/프로젝트 revision/정렬 결과가 바뀌면 이전 비교를 표시하지 않습니다.

실제 GUI에서 양쪽 영상 정상 표시와 `양쪽 영상 로드 완료`를 확인했습니다. v2.2.4의 일시적인 검은 영상 원인은 확정하지 못했으며 이번 변경으로 모든 렌더러 문제를 해결했다고 주장하지 않습니다.

## 모듈과 좌표 계약

- `algorithms/roi_alignment.py`: 점 방향 적합, ROI 회전/box 변환, 확률의 원본 ROI 복원만 담당.
- `sam_service.ModelService.in_roi`: 기존 독립 ROI 경로에서 옵션 사용 시에만 호출. 정렬 영역 밖 support는 제거하고 확률을 bilinear 역보간한 뒤 모델 threshold 적용. prompt box로 mask를 강제 잘라내지 않음.
- 원본 candidate mask 크기/좌표와 `inference_domains`는 그대로. `roi_alignment`에 local↔aligned 행렬, 크기, box, fit을 기록. 행렬의 local은 ROI 내부 좌표이며 원본 영상 전역 좌표가 아님.
- 정렬된 SAM logits/context를 원본 좌표 logits인 것처럼 재사용하지 않음. 원본 점 기준 위반 검사를 다시 실행.
- 사전정렬은 최종 계측 좌표 변환과 별개. 기존 crop unknown/GT/회전 guard 유지.
- `roi_editor.js`는 옵션/미리보기 만료, `roi_review.py`는 실험 경고, `metrology.js`는 비교 이미지 load/decode gate 담당.

## 남은 우선순위

직선 방향을 안다고 물질 경계를 아는 것은 아닙니다. 얇은 층의 후보 순위, 누출/분절, ROI와 수동점의 민감도, 비직선 구조, 확대/축소에 따른 box 여백 의존성은 미해결입니다. 프롬프트 재사용 일괄 파이프라인에 이 옵션을 연결하려면 ROI·방향·폭의 영상별 검토와 실패 격리가 먼저 필요합니다. 전문가 GT 없이 score 최댓값이나 45° 근접값을 자동 정답으로 채택하면 안 됩니다.

참고: SAM의 공식 point/box 및 다중 후보 인터페이스는 [Meta SAM 저장소](https://github.com/facebookresearch/segment-anything), 기하 역매핑/보간의 구분은 [OpenCV 변환 문서](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)를 확인했습니다. 이 자료가 본 TEM 경계 정확도를 보장하는 것은 아닙니다.
