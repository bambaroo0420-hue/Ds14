## 2. 사용자 의도와 동작 검토

- **분할 먼저, 배정 나중:** 실제 일괄 SAM 결과는 미배정 후보로 남았습니다. Grid·feature 점 준비를 SAM 실행으로 오인하지 않도록 버튼을 분리했습니다.
- **필요한 대상만:** 3개 영상에서 수동 그룹 결과 2개만 선택 집합에 저장하고 GT 없이 일괄 회전/두께/CD를 실행했습니다. 미선택 영역을 강제로 background로 만들지 않습니다.
- **어디를 어떻게 변경하는지:** 선택 집합과 편집 A를 구분하고, GT 변경 제안·회전 기준점·계측 선을 실제 결과 좌표로 그립니다. UI 시안의 가짜 선을 결과로 쓰지 않습니다.
- **자동화와 검수 분리:** 프롬프트 변환, OCR 축척, 경계, 회전은 제안과 확정을 구분합니다. stale 결과와 보호 영역은 자동 강행하지 않습니다.
- **일관된 계측:** 기준 mask/edge/ROI와 표본 구간을 고정할 수 있지만 SAM 경계 자체가 달라질 수 있습니다. 실제 밝기/노이즈 시험에서도 전체 구간 두께 평균 110.698/129.583/122.238px로 달랐습니다. 검수 없이 같은 숫자가 나온다고 보증할 수 없습니다.

## 3. 코드 최종 검토에서 수정한 사항

| 발견 | 보완 | 확인 |
|---|---|---|
| 빈 ROI 복사 버튼이 기존 회전 구간을 null로 덮음 | 미지정이면 안내하고 기존 값 보존; 메인 ROI 도구 명확화 | UI 로직 + 실제 드래그 ROI로 0° 합성 경계 회전 제안 |
| 다중 선택 0으로 보이지만 편집 A가 실제 단일 대상 | 실제 대상을 `1개 대상 (편집 A)`와 행 선택 표시로 일치 | UI 로직/화면 |
| 단일 mask는 레이어 색 대신 고정 초록 | 해당 레이어 색 사용 | 코드·재로드 화면/기존 회귀 |
| 새 근거창의 무한 로딩 가능성 | 기존 검증된 15초 decode/timeout 로더 재사용, image/revision 검사 | 로더 회귀 + 실제 근거창 |
| ROI token과 요청 image_id 불일치 허용 | 저장 전에 동일 영상 검사 | API 음성 시험, 후보 미생성 확인 |
| Recipe 미리보기 후 재저장 시 정책/feature 설정 누락 | 반환 draft와 UI 설정 복원 | API·UI 로직 |
| HTML5 행 drag가 내장 브라우저에서 배정되지 않음 | 명시적 pointer 손잡이, 선택집합/영상ID 고정, API 잠금 검사 유지 | 실제 2mask 드래그→2개 배정→Undo로 각각1개 복원, 로직 시험 |

처리 경로의 저장 트랜잭션/롤백, 레이어 잠금, 원본 좌표/ROI 영역 제한, 오래된 입력의 재사용 차단, source-only 패키지 범위를 점검했습니다. 테스트 결과가 코드 무결함의 수학적 증명은 아닙니다.

## 4. 최종 증거와 배포 검사

- Python: **198개 통과**, 오류/실패/skip 0. 관리형 Windows 임시폴더 ACL 우회 여부도 기록했습니다.
- JavaScript UI: **8개 묶음 통과**. 최신 workbench suite는 단일/다중 대상, pointer 배정, Recipe 설정 복원, 회전 ROI, 근거창 안전 로더 연결을 검사합니다.
- 실제 SAM ViT-B CPU, EasyOCR, API, 브라우저 주요 동작을 수행했습니다. 수치/실패/모델 조건은 `V230_IMPLEMENTATION_KO.md` 참조.
- 템플릿 생성/복사, layer/candidate 이름 대화상자, 드래그/Undo, 잠금, 회전 ROI와 근거창은 실제 화면에서 확인했습니다. 해당 브라우저 콘솔 error 0건. 다른 입력 조합/모든 버튼의 무결함은 보증하지 않습니다.
- ZIP은 명시적 소스 manifest만 포함하고 CRC·204개 이상 파일 해시·Python 구문을 검사합니다. 최종 파일 수/용량/SHA256은 ZIP 옆 `verification.json`, `SHA256SUMS.txt`를 기준으로 합니다. 배포본을 별도 압축 해제하여 회귀 테스트도 실행합니다.
- Git에는 기존 작업 브랜치/PR만 갱신합니다. 관계없는 기존 ZIP 삭제는 stage하지 않습니다. 사용자 영상·모델·프로젝트·원시 로그는 업로드하지 않습니다.

로컬 GUI 추가 증거: `test-output/v230-gui/final-rotation-roi.png`, `final-workbench.png`, `final-drag-assignment.png`. 실제 19 기반 회전/계측 화면은 `test-output/v230-real-2/gui-rotation.png`, `gui-measurement.png`입니다. 공개 소스 패키지는 이 로컬 영상 자료를 포함하지 않습니다.

## 최종 결론

v2.3.0은 v2.2.9의 기능을 보존하면서 **대상/레이어 시각화, 그룹 Recipe, ROI 자동 후보, 경계/회전/계측 근거**를 실제 동작으로 확장한 버전입니다. 남은 항목 때문에 “대화의 수정사항 전부 완료”로 표시하면 안 됩니다. 회사 적용은 프로젝트 사본에서 기준 layer·표본 구간·축척을 검수한 뒤 승인해야 합니다.
