# v2.2.9 오류 수정과 배포 검토

이 문서는 5시간 자동화가 종료된 뒤 사용자가 요청한 별도의 오류 수정·ZIP 배포 작업이다. 이전 버전의 실제 모델/영상 결과와 이번 회귀 검증을 구분한다. 회사 원본·전문가 GT·회사 PC의 traceback은 제공되지 않았다.

## 수정 범위

| 항목 | 변경 및 판단 |
|---|---|
| WinError 5/32 임시 파일 저장 | `storage.atomic_json`에서 교체 시 제한적 재시도, 파일 핸들은 교체 전에 닫음. cleanup 실패는 경고로 남기고 최초 오류 보존 |
| prepared SAM 후보 저장 | `v2_api.transaction`과 `Project.save`에서 해당 요청의 중간 메타데이터 저장을 지연. 후보 3개 대조군에서 실제 JSON 저장 8→1회. 원본 이미지 보존 |
| 부분 성공 뒤 실패 | 메타데이터를 최종 한 번 게시하므로 이번 경로의 이전 JSON을 유지. 실패 과정의 참조되지 않는 후보 PNG는 남을 수 있으며 자동 삭제하지 않음 |
| 지속 오류·복구 실패 | 상태 API와 HTTP503으로 사유 표시, 후속 변경 요청 및 직접 save 차단. 조회는 가능. 원인 해결/백업 후 서버 재시작 필요 |
| 이미지 읽기 | 손상된 입력, multipart 임시 파일 read, 출력 이미지/metadata 쓰기 실패를 구분. 손상된 입력만으로 전체 프로젝트 편집을 차단하지 않음 |
| uvicorn 누락 | 실행 Python 경로와 필수 모듈 누락을 출력. install/start/diagnose BAT 분리, 일상 실행 시 설치·네트워크 작업 없음 |
| 스케일 검출 후 확정 | 미적용 제안을 실패로 오표시하지 않고 표에서 상태 구분. 미적용 값 저장→사용자 확정→1 이미지·스케일 표시 갱신. 신선도 검사·기존 유효 스케일 덮어쓰기 방지 |

## 검증 기록

- 스테이징 전체 Python unittest 169개 PASS (최종 재실행 32.001초). 실제 앱 소스를 사용하며, SAM 모델 추론은 회귀 테스트에서 모사한다. Windows 샌드박스의 임시 디렉터리 ACL 차이를 피하기 위해 workspace 내 별도 테스트 폴더를 사용했고 증거를 보존했다.
- 6종 Node 화면 로직 테스트 PASS. 처음 잘못된 NODE_PATH에서 canvas 개발 의존성을 찾지 못했으나, 기존 번들 의존성 경로로 바로잡아 전부 통과했다. 사용자 앱 런타임 오류와 구분한다. 스케일 확정과 제외 영역 적용의 상태 표시 분리도 검사했다.
- 실제 Windows 임시 파일 공유 잠금 후 해제: SAM 요청 정상 완료. 제한적 재시도/최초 오류 보존/중간 실패/편집 차단/재시작 저장 상태 검증 포함.
- 1 MiB 초과(약2.4 MiB) PNG multipart 실제 읽기·원본 픽셀 대조·썸네일 제공 PASS. 비이미지 및 모사 임시 read 실패는 별도 안내.
- `python -S run.py`로 site-packages 없는 환경에서 누락 안내·정상 오류 종료 확인. 실제 회사 PC의 설치 또는 모든 Python/CUDA 조합을 검증한 것은 아님.
- 실제 브라우저: 별도 프로젝트에 19.jpg 기반 기울어진 crop 2장 업로드/표시 확인. 실제 모델·GUI 상세 결과는 다음 절에 기록했다.

## 실제 구동 결과 (2026-09-30)

기존 프로젝트를 변경하지 않는 별도 로컬 서버/프로젝트에서 검증했다. 테스트 영상은 `19_crop_1cell_+07deg.png` (392×553), `19_crop_3cell_-08deg.png` (949×636)이다. 후자는 19.jpg에서 반복 배치한 합성 montage이며 독립적인 회사 실측 표본이 아니다. 아래 nm 값도 테스트 축척을 적용한 값이다.

| 실행 경로 | 결과 |
|---|---|
| GUI 모델 로드 → Grid → 추가점 → prepared SAM | 실제 SAM ViT-B CPU, Grid 16점 + Sobel/median 3점, 후보 7개, 추론 요청 12.860초, 저장 성공 |
| 실제 EasyOCR 문자·바만 일괄 검출 | 2/2 성공, 각각 3개 영역, 100 nm/81 px → 1.2345679012 nm/px. 제외 영역 적용 안 함 |
| GUI 스케일 검토 표 | 처음에는 “검출됨·아직 미적용”, 저장 후 확정. 최종 2장 모두 “확정됨”; 1번 화면도 확정값으로 갱신. 기존 제외 박스 불변 |
| 표시 혼동 회귀 | 이미지 등록만으로 “적용” 집계하던 표시 수정. “제외 적용 0 / 스케일 확정 2 / 실패 0”으로 각각 표시 |
| 레이어 미지정 후보 #1만 선택 | 오른쪽 기둥을 육안 확인해 선택 집합 저장. 7개 후보 모두 layer 미지정 상태 유지 |
| GT 없이 회전·계측·내보내기 | 위쪽 edge 기준 +8.1664°, 기준점 잔차 0.3556 px. GT 없는 결과 ZIP 187,550 bytes 생성 |
| 같은 선택 범위의 부분 GT + 두께/CD | 부분 GT 검수 후 두 방향 재계측, ZIP 안에 partial_gt, 변환/역변환, 두 방향 JSON, CSV 182행(헤더 제외) 확인 |
| 서버 종료·재시작 | 이미지 2장, 후보 7개, 확정 축척, 선택 범위 및 회전·두 방향 결과 유지. 재시작은 모델을 다시 메모리에 로드해야 한다는 뜻이지 패키지 재설치가 아님 |
| 환경 검사 | 기존 검증 가상환경 `pip check`: No broken requirements found. 회사 PC 환경은 별도 확인 필요 |

반례도 함께 보존했다. 큰 면적만 기준으로 고른 후보는 아래 문자 띠여서 잘못된 회전 기준이 됐다. 후보 #1 위쪽 기준은 알려진 -8° 기울기를 대략 복원했지만, 아래쪽 기준은 +6.7504°, 영상 주 방향은 -0.5155°로 불일치했다. 자동 추천을 무조건 확정하면 안 된다.

계측은 두께 유효 9개(평균 136.5643 nm, 표준편차 75.8069 nm), CD 유효 15개(평균 75.8075 nm, 표준편차 4.0958 nm)였다. 두께에는 가장자리의 짧은 조각까지 들어가 편차가 크다. **이 숫자를 물질의 정확한 두께/CD로 인정한 것이 아니다.** 범위/마스크 검수 및 전문가 비교가 필요하다. 검수 상태 변경 후 이전 계측 내보내기는 stale 오류로 차단되어 두 방향 모두 재계산했다.

로컬 증거 파일명: `sam-real-gui.png`, `scale-confirmed-gui.png`, `ocr-job.json`, `metrology.json`, `metrology-area-counterexample.json`, `selected-mask-results.zip`. 원본/영상/모델/개인 경로가 포함된 실행 산출물은 공개 소스 ZIP에서 제외했다.

## 안전과 배포

- 소스 ZIP에는 모델·회사 영상·테스트 프로젝트·.venv·개인 경로가 담긴 실행 결과를 포함하지 않는다. 실행 후 모델 설치는 별도이며 source ZIP만으로 완전 오프라인 실행 가능한 설치 패키지라는 의미가 아니다.
- 기존 프로젝트에 덮어쓰지 말고 새 앱 폴더+백업을 사용한다. 동일 프로젝트의 다중 서버 쓰기, 프로세스 강제 종료/전원 장애까지 완전한 DB 트랜잭션을 보장하지 않는다.
- JSON 1회 저장 최적화는 `/api/sam/prepared`에 한정된다. 모든 batch 단계의 중간 저장 구조는 이번 배포에서 전면 재설계하지 않았다.
- 코드와 ZIP은 기존 `codex/tem-v2-batch-metrology`/PR #1에 반영하며 main에 병합하지 않는다. 기능 실행 성공과 계측 정확도를 동일시하지 않는다.
