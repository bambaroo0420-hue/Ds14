# TEM Analyzer UI 재설계 검토안

작성: 2026-09-30. 대상: 로컬 v2.2.9 코드 및 사용자 추가 요구.

이번 작업은 **설계·UI 시안 단계**이다. 앱 코드, 모델, 프로젝트 데이터, GitHub 배포본은 변경하지 않는다. 시안의 마스크·숫자·gradient는 동작 설명용 생성 예시이며 19.jpg 또는 실제 SAM 실험 결과가 아니다. 사용자 환경의 독립 ROI 실패는 이번에 실제 모델로 재현하지 않았으므로 해결됐다고 판단하지 않는다.

## 1. 추가 질문에 대한 현재 코드의 답

### 독립 ROI SAM 후보

`web/roi_editor.js` → `/api/sam/prompt` → `SamService.in_roi()` 경로는 존재한다. 현재는 ROI를 잘라 **수동 양성/음성점 또는 SAM box로 한 객체를 추론**한다. ROI만 지정하면 자동 후보를 생성하지 않는다. Grid/ML 다중 객체 생성을 독립 ROI 편집기에서 실행하는 경로는 없다.

현재 조절 가능한 것은 후보 자동/1/2/3, 양성점 사전정렬, 사전정렬 box 여백이다. 후보 선택 변경은 현재 미리보기를 무효화한다. 다시 ‘재분할 미리보기’를 실행해야 새 결과가 나타나는 구조다. 모델/이전 마스크 입력 경로에 따라 단일 후보만 지원할 수 있으며, 지원하지 않는 2/3번을 선택하면 오류가 난다. 예측점수는 물질 경계 정확도가 아니다.

현재 실행 전 사용자 오류를 분리해서 보여주는 설계가 부족하다. 특히 ROI만 있는 상태, 모델 미로드, ROI 밖 점, 제외영역 점, 지원하지 않는 후보 번호, 사전정렬 조건 부족, 빈 결과, 미리보기 로드 실패, 저장 실패를 따로 구분해야 한다. 실패 원인을 실제 환경에서 재현·분류하는 것이 구현 첫 검증 항목이다.

### 일괄 SAM에 수동/ML 레시피가 적용되는가

| 현재 일괄 선택 | 수동 점·box | Grid 점 | ML/특징 점 | 의미 |
|---|---|---|---|---|
| Grid | 적용 안 함 | 대상 영상에서 새로 생성 | 없음 | 저장 recipe와 별개 |
| ML/특징 | 적용 안 함 | 없음 | 대상 영상에서 새로 생성 | 현재 feature 설정 사용 |
| Grid+ML/특징 | 적용 안 함 | 대상 영상에서 새로 생성 | 대상 영상에서 새로 생성 | recipe 수동점 자동 결합 안 함 |
| 저장·검수한 재사용 프롬프트 | 저장 당시 점·box를 좌표 변환하여 사용 | 저장된 자동점에 포함됐다면 재사용 | 저장된 자동점에 포함됐다면 재사용 | 이미지별 준비·미리보기·확정 필요 |

근거: `web/bridge.js`의 `promptDraft()`는 Grid/ML을 하나의 `auto_points`로 합쳐 저장한다. `services/prompt_transfer.py`는 수동점·box와 이 자동점을 변환한다. `services/prompt_batches.py::run_transferred()`는 자동점 SAM과 수동 객체 SAM을 각각 실행한다. `routes/workflow.py`의 일반 Grid/feature 경로에는 recipe 수동점이 들어가지 않는다.

따라서 **재사용 모드라면 수동점과 저장한 ML 점이 둘 다 사용될 수 있으나, ML 알고리즘을 대상 이미지에서 다시 실행하는 것은 아니다.** `feature_settings`가 저장돼 있어도 재사용 실행에서 새 점 생성에 쓰이지 않는다. 자동점은 Grid와 ML 출처가 분리돼 있지 않다. ROI 편집기 점·box는 후보의 provenance로 남지만 메인 화면 preset 저장과 자동 연결되지 않는다. 여러 Manual 객체 그룹도 아직 없다.

기존 수동점 `independent` 모드는 양성점마다 별도 후보를 만든다. `object` 모드는 수동점·box를 한 객체로 묶는다. 이것은 모델의 대안 후보 1/2/3과 다른 개념이다.

## 3. 권장 화면 배치와 시안

### A안: 고정 작업대 — 권장

상단: 이미지 / 활성 레이어 / 선택 수 / 작업 단계. 좌측: 레이어 트리와 포함 mask, 표시·잠금. 중앙: 큰 영상과 입력/미리보기. 우측: 현재 작업에 필요한 설정만. 중앙 하단: 선택 후보와 가까운 배정 버튼. 독립 ROI도 이 구조를 쓰며 확대 작업공간으로 전환한다. 세로로 길게 흩어진 기존 기능은 단계별로 모은다.

### B안: 캔버스 우선

같은 기능이지만 레이어/후보 목록을 하단으로 도킹하고 영상·작업설정을 크게 쓴다. 작은 화면이나 발표에 유리하지만 레이어 비교 가시성은 A안보다 떨어진다. 패널 위치 고정은 편집 잠금과 별개이며 위치만 저장한다.

이번 대화 시안은 SAM·레이어, 독립 ROI, 경계·GT, 회전·계측, 일괄 recipe 탭을 제공한다. 다중 선택, 패널 도킹, 모드별 설정, 후보 전환, GT 전후, 회전 전후, 측정 행 강조를 로컬 예시로 확인할 수 있다. 실제 추론·저장·데이터 변경은 하지 않는다.

## 4. 독립 ROI 구체 설계

| 모드 | 입력 | 노출 설정 | 출력 |
|---|---|---|---|
| 수동 객체 | +/−점, SAM box, Manual 그룹 | 후보 비교, 사전정렬/여백, 전처리, 선택적 마스크 이진화 임계값(고급·검증 후) | 한 객체의 대안 후보, 지원 개수만 표시 |
| ROI 자동 후보 | ROI + Grid/feature/Grid+feature | Grid 밀도, feature 방식/간격/최대점수, IoU 예측점수·안정성·NMS 필터, 전처리 | 여러 객체 후보와 필터 탈락 요약 |

ROI는 추론 영상 범위이며 SAM box는 객체를 가리키는 입력이다. 둘을 다른 선·라벨로 표시한다. ‘후보 1/2/3’은 같은 객체의 대안이지 Manual 1/2/3이 아니다. 기본 SAM이 반환한 대안은 캐시해 선택만 바꾸면 즉시 비교하도록 설계한다. 입력/전처리/모델 변경 시 캐시 무효화와 재실행 필요 상태를 표시한다. 데이터량 제한과 단일 마스크 모델의 capability를 확인한다.

자동 후보용 score/stability/NMS는 수동 객체 결과 선택을 바꾸는 설정이 아니다. 동일 화면에 무조건 노출하지 않는다. 최소 영역 크기·이진화 임계값을 추가한다면 단위·적용 위치·얇은층 손실 위험을 명시하고 기본값으로 임의 삭제하지 않는다. 화면 예시 숫자는 확정 기본값이 아니다.

실행 전 상태: 모델 → ROI → 유효 입력 → 실행 가능. 실행 후 상태: 추론 완료 → 후보 미리보기 → 새 후보 저장 → 레이어 미배정. 빈 결과는 성공으로 숨기지 않고 점·필터·제외영역·절단 여부를 제시한다.

## 5. 일괄 recipe v2 설계

recipe는 단순 좌표 모음이 아니라 실행 계획이다. 아래 내용을 버전과 함께 저장한다.

- 기준 이미지/크기/해시, 모델 종류·체크포인트 식별자, 전처리·제외 정책.
- `manual_groups`: 객체마다 고유 ID, +/−점, box, ROI, 부모 대응, 잠금·이름.
- `grid`: 사용 여부·밀도·ROI별 좌표 재사용 또는 대상에서 재생성.
- `features`: Canny/Sobel/K-means/프로파일 등 출처, 파라미터, 좌표 재사용 또는 대상 영상에서 재생성.
- 좌표 변환 방식·행렬·원본좌표계; 위치 정합은 의미/물질 일치 보장이 아님.
- 후보 필터, 중복점 제거 기준, manual-자동 후보 간 중복 처리 정책, 캐시 버전.

권장 초기 정책은 **수동 그룹은 정합 후 재사용 + feature는 대상별 재생성**, 단 사용자가 정책을 선택하고 결과 점들을 검토해야 한다. Grid도 별도로 켠다. 옮긴 수동점과 새 feature 점을 한 객체 입력으로 무조건 합치지 않는다. 자동점은 독립 객체 탐색, 수동점은 그룹별 객체 제약으로 실행한다.

부모 내부 ROI recipe를 다른 이미지에 적용하려면 부모 후보 대응이 필요하다. 부모 ID만 복사하지 않고 대응을 확인한다. 대응 없으면 명시적으로 ‘부모 없는 독립 ROI로 변환’하거나 해당 그룹을 보류한다.

일괄 표: 이미지 | recipe/version | 수동 그룹/점수 | Grid 점수 | feature 방식/점수 | 재사용/재생성 | 좌표/제외 검사 | 검토 | 실행 | 후보수 | 오류. SAM만 먼저 전부 실행하고 layer 배정은 나중에 가능하다. 미검토·정합 실패·범위 밖 입력을 조용히 이전 recipe 또는 기본 Grid로 대체하지 않는다. 기존 후보는 보존하고 run_id로 구분한다.

## 6. 시각화 계약과 논리

### SAM·레이어

색은 클래스 표시일 뿐 Semantic GT는 클래스 ID와 valid/unknown/excluded 정보다. 색 변경은 GT ID를 바꾸지 않는다. 선택은 두꺼운 윤곽/ID 라벨로 표시하고 층 색만으로 선택 여부를 구분하지 않는다. 한 레이어의 union과 개별 후보를 모두 볼 수 있어야 한다.

### 경계·GT

미분할 영역은 자동 배경이 아니라 Unknown이다. 확실한 배경만 명시적으로 지정한다. 같은 클래스의 후보 병합과 다른 클래스 A/B의 공유 경계 재분배를 구분한다. 다른 클래스를 하나로 합쳐 ID를 잃지 않는다.

현재 후보 간 보정은 전체 영상에 conflict가 있으면 먼저 해결하라고 차단하는 반면, 레이어 자동 제안은 일부 제한된 겹침/틈 처리가 가능하다. 이 기능을 동일 화면에서 ‘충돌 검사 → 대상/허용 폭 지정 → 초기 분배 → Gradient+DP → 실제 적용 가능 마스크 → 검수’로 연결한다. 실제 공간적 인접 관계와 사용자가 지정한 A/B를 함께 확인하며 레이어 목록 순서만으로 인접을 확정하지 않는다.

색/선: 원래 경계=회색 점선, peak=주황 점, DP 제안=청록 실선, 실제 적용선=굵은 클래스 윤곽, 잠금=아이콘+해칭. 겹침과 틈은 다른 해칭. 법선 클릭 시 동일 점의 거리(px)-gradient 곡선과 선택 offset을 연동한다. 잠금·배경·제외·Unknown 영역까지 무조건 채우지 않는다. 폐곡선 제안이 보호 조건으로 제한된 경우 실제 최종 mask 윤곽을 따로 표시한다.

### 회전·계측

회전 기준과 측정 대상은 분리한다. 실제 사용한 상부/하부/직접점·ROI와 inlier/outlier, 피팅선, 각도, 잔차·경고를 표시한다. 자동 경계 대체가 일어나면 UI에 선택했던 이름이 아니라 실제 사용 경계를 표시한다. 기준이 무효해지면 회전/계측 확정을 무효화하고 사유를 표시한다.

회전 후 두께는 수직, CD는 수평 샘플선으로 구현된 현재 정의를 화면에 표시한다. 곡선 경계의 국소 법선 두께는 별도 방법이며 구현 없이 같은 기능으로 설명하지 않는다. 이미지·mask·ROI·샘플점은 하나의 변환과 역변환을 공유한다. 측정값은 원본 샘플링과 변환 메타데이터를 보존해 재현한다. 필수 layer 전체/GT 확정 없이 선택 mask만으로 회전·잠정 계측 가능하다.

프레임/ROI 절단, 제외영역 통과, 다중 교차, 잘못된 scale은 측정선 색과 표의 사유로 표시한다. 데이터 행 클릭 시 실제 두 끝점·교차 구간을 강조한다. 수치 없는 시각화, 위치 없는 수치표를 피한다.

## 7. 구현 전후 검증 기준

1. 독립 ROI 문제 재현: 기본 SAM·단일 후보 모델, 점/box/ROI 조건별 오류, 후보 전환, 저장/취소, 원본좌표 복원. 로그와 화면 증거를 남긴다.
2. 다중 선택: Ctrl/Shift·범위선택 결과와 화면 강조 ID가 정확히 일치. 잠긴 후보 삭제/이동/brush 차단. 다른 이미지로 넘어갈 때 선택 누출 없음.
3. ROI 자동 후보: 실제 Grid/feature 분기 호출, 탈락 수, 빈 결과, 적용되지 않는 파라미터 검증. 미리보기 선택만으로 불필요한 재추론하지 않음.
4. recipe: manual 그룹 2개 이상+Grid+feature를 3장 이상에 실행. 재사용/재생성 실제 입력과 UI 점수/출처가 일치. ROI 부모 대응 실패를 숨기지 않음.
5. GT: 생성 정답의 겹침/틈/비인접 충돌/잠금/배경 예제. 선택 A/B 밖 불변, 허용 범위 밖 불변, 클래스 ID 유지, Undo·재시작 복원.
6. 회전: 기울어진 19.jpg 파생본과 알려진 각도의 생성 mask. 사용한 실제 피팅점·각도와 표시 일치, 45° 사례 포함. 정합/방향 추정 실패도 결과에 남김.
7. 계측: 알려진 두께/CD mask의 숫자, 표시 끝점, 변환 왕복, CSV 행 일치. GT 없이 특정 mask만 선택한 일괄 경로 포함.
8. UI: 1366×768·1920×1080 화면, 접기/도킹/확대, 큰 발표 미리보기, 키보드 조작, 배경 작업 중 상태, 실패 복구·저장 충돌.
9. 발표 출력: 범례·좌표·설정·원본/변환 표시 누락 없음. 생성 예시와 실측 결과를 명확히 구분.

19.jpg 기반 기능 검증은 회사 영상/전문가 GT 정확도 검증을 대체하지 않는다. 이번 작업에서는 정적 코드 검토와 시안의 인터랙션 검토만 수행하며 실제 SAM 실패 재현 및 위 회귀시험은 앱 구현 단계의 완료 조건으로 남긴다.

## 8. 수정 순서

1. 대상/선택 상태 통합, 상단 고정, canvas overlay 체계.
2. 독립 ROI 실패 재현·수정, 모드/파라미터/후보 비교.
3. 다중 선택·배정·palette·lock, GT 작업공간.
4. 실제 회전 기준/샘플선 시각화와 표 연동.
5. Manual 다중 그룹과 recipe v2, 일괄 적용 감사표.
6. OCR 지역 재검출/제외 검토, 발표 export, 새 버튼 매뉴얼, 실제 GUI·모델 회귀검증.

모든 변경은 미리보기·확정·취소/Undo와 저장 상태를 함께 설계한다. 계획의 기능을 구현 완료로 표시하지 않는다.
