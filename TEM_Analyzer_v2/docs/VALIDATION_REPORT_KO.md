## 요청한 19.jpg 경로: GT 없이 회전

`tools/create_19_demo.py`가 crop → 회전 → 바깥 20 px crop → 실제 SAM 프롬프트 → 레이어 배정 → 회전 → 잠정 두께 계측을 실행했습니다.
경계 보정과 GT 생성은 실행하지 않았고, 마스크도 검수 전 상태로 남겼습니다.

| 시험 예제 | 추가한 회전 | 추정 보정각 | 무회전 기준 대비 상대 각도 오차 |
|---|---:|---:|---:|
| 1 cell | +7° | −6.7529° | +0.1627° |
| 3 cells | +7° | −6.9268° | +0.0732° |
| 3 cells | −8° | +7.9482° | −0.0518° |

1-cell 무회전 영상의 추정 보정각은 +0.0844°, 3-cell은 0°였습니다.
1-cell은 중앙 경계 구간, 3-cell은 각 마스크 위쪽 경계의 대표점을 사용했습니다.
자동 기준 선택은 같은 정책이며 API 테스트 및 3-cell 브라우저 재계산으로 확인했습니다.

3-cell은 같은 구조를 반복한 **합성 montage**입니다. 독립 촬영 영상 3개의 성능을 뜻하지 않습니다.
추가한 배율/스케일/문구 역시 검출 테스트용 표기입니다. 실물 두께의 정확도 검증에 사용하면 안 됩니다.
절대 두께/CD 검증은 별도의 수식 기반 합성 마스크에서 수행했습니다.

로컬 증거: `test-output/crop19-v22/validation.json`, `test-output/real-models-v22/real_model_validation.json`.
입력 사진과 증거 이미지는 공개 저장소에 업로드하지 않습니다. 생성 스크립트로 재현하세요.

## 최종 검토에서 수정한 문제

1. 선택된 기본 위치 템플릿이 자동 검출 박스처럼 표시되던 문제: legacy/OCR 상태 및 표시·분석 제외 경로를 분리.
2. scale bar 대신 문자 획을 선택하던 문제: 길이·문자 상대 위치 필터, 기울어진 연결 성분 분석. OCR padding 때문에 진짜 바가 거부되는 경우도 수정.
3. 회전·계측을 GT 후 단계처럼 안내하던 문제: 독립 경로, 잠정 계측 표기 및 GT 없는 결과 ZIP.
4. 이미지/마스크/제외 영역 변경 뒤 과거 회전·측정을 재사용할 위험: 입력 해시 및 stale 검사.
5. 좁은 브라우저 초기 크기에서 캔버스가 맞지 않던 문제: 리사이즈 시 fit·이동값 재계산 및 반응형 레이아웃.
6. native 삭제 확인창과 이전 JS 캐시로 UI 검증이 멈추던 문제: 비동기 확인창과 UI 자원 버전 갱신. 새 탭에서 삭제·Undo/복원 성공 확인.

## 범위와 남은 한계

- 회사 이미지의 검출률·물리적 계측 정확도, CUDA 성능, 다양한 촬영 양식은 검증하지 못했습니다.
- SAM의 구멍/부스러기/거친 경계는 자동 회전 후에도 남습니다. 잠정 계측은 최종 GT 정확도를 보장하지 않습니다. 필요하면 마스크 편집·경계 보정·검수를 수행하세요.
- 회전은 강체 회전이며 휘어진 층을 펼치지 않습니다. 잔차가 크면 기준 구간/대표점을 조정하세요.
- OCR의 복수 후보·약한 대비·접촉한 문자/바는 수동 확인이 필요합니다. 자동 검출은 확정값이 아닌 제안입니다.
- 레이어 자동 대응은 정규화 공간 중첩 기반이며 물질 분류 모델이 아닙니다.
- 취소는 현재 추론 단계 종료 후 반영됩니다. 무중단 추론 강제 종료가 아닙니다.
- 드래그 구현은 포함되어 있으나 모든 브라우저/OS에서 drag-and-drop E2E 조합을 검증한 것은 아닙니다. 버튼 배정도 제공합니다.
- 회사망 반입 절차 및 대상 PC의 패키지/모델 라이선스 승인은 별도입니다.
