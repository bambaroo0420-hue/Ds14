# TEM Analyzer 목적 재점검·실제 기능 감사

검증일: 2026-10-01 / 대상: 기존 v2.2.9 / 판정: **핵심 처리 경로는 실행되지만, 사용자 요구 전체를 충족한 완성품으로 승인할 수 없음.**

디자인 시안이 아닌 기존 Python 서버·실제 브라우저·실제 SAM ViT-B/EasyOCR로 시험했다. 생산 코드 수정·Desktop 동기화·GitHub 배포는 하지 않았다. 이 문서는 기능 감사이며, 회사 이미지의 정확도 인증이 아니다.

## 1. 프로젝트의 목적과 승인 기준

목적은 비슷한 구조의 여러 TEM 이미지에서 **SAM을 먼저 일괄 실행 → 필요한 mask만 선택·수정·layer 배정 → 필요한 경우 부분/semantic GT와 공유 경계 보정 → 동일한 기준으로 회전·두께/CD 계측 → 근거와 좌표를 함께 저장**하는 것이다.

| 목적 | 반드시 필요한 조건 | 이번 판단 |
|---|---|---|
| SAM 선처리 후 나중에 layer 정리 | 기존 후보 보존, 일괄 결과 미배정, 선택 대상 확인 | 실제 실행됨. 다중 선택 overlay 결함 있음 |
| Recipe 자동화 | Grid/특징점/수동 +/−점/box 보존, 변환 검토, 별도 SAM 실행 | 저장·재로드·두 이미지 실제 추론 및 GUI ECC 재사용 확인 |
| 필요한 mask만 GT/계측 | 전체 layer 구분 강제 금지, 미선택은 unknown | 선택 집합 저장·부분 GT·GT 없는 계측 경로 확인 |
| 경계 보정 | 인접 충돌·틈·배경을 구분, 원본/변경/보호 영역 표시 | 합성 경계에서 실행됨. 순서 안내·실제 TEM 검증 부족 |
| 일관된 계측 | 기준 mask/edge/구간·좌표 변환·표본 기준 고정 | 두 축 및 일괄 처리 확인. 회전 ROI 연결 누락, 시각화 부족 |
| 안전한 재작업 | Undo/Redo, 삭제 복원, 만료 차단, 작업 취소 | 실제 시험에서 확인. 다운로드 파일 저장은 브라우저별 추가 확인 필요 |

GT나 경계 보정은 회전·계측의 필수 선행 조건이 아니다. 미검수 mask의 결과는 잠정값이어야 한다. 자동으로 모든 빈틈을 배경으로 채우거나 모든 후보를 layer에 넣는 것은 목적에 맞지 않는다.

## 4. Recipe·Grid·특징점·수동점

실제 API/모델 시험:

- Grid 4 + Canny 2 + 수동 +/−점 2 + box를 저장·디스크 재로드했다. feature 설정도 보존됐다.
- 두 이미지에 Recipe 준비 → 검토 확정 → 실제 SAM: 첫 영상 자동5+수동1, 두 번째 자동4+수동1. 약 75.7초. 신규 후보는 모두 layer 미배정이었다.
- 일반 일괄 SAM은 Grid/특징점만/Grid+특징점 각각 실행되어 4/3/5개 후보를 만들었다. 이는 별도 경로이며, **일반 Grid+특징점 실행에 수동 Recipe가 자동 합쳐지는 구조는 아니다.**
- K-means/Canny/Sobel/Scharr/혼합은 제안점 생성. Profile 방식은 방향이 약한 이 영상에서 0점과 경고를 반환했다. 경고 처리는 정상이나 유용한 점을 찾은 성공으로 세지 않는다.

실제 GUI 시험:

- 모델 로드, Grid 생성, Canny+Gaussian 제안 미리보기·추가, 수동 +/−점과 box, 표시 켜기/끄기, Recipe 저장, 준비한 프롬프트 SAM 버튼을 직접 조작했다.
- Canny 점 두 개가 물질이 아닌 montage의 회색 padding에 놓였다. **특징점 생성 성공 ≠ 유효한 물질 prompt**이다. 분석 domain/패딩 제외가 필요하다.
- ECC 이전은 0.922의 정합값, 영상 밖/제외 영역 자동점 2개 제거 경고를 표시했다. 변환 후 자동4+수동2+box로 SAM을 실행하여 자동4+수동1 후보를 추가했다. 약 35.7초.
- ‘추가점만 지우기’는 ML 2점을 지우고 Grid4·수동2·box1을 유지했다.
- 여러 독립 수동 객체 `manual1/manual2/...`와 ROI 추론 이력을 통합 Recipe로 저장하는 기능은 아직 없다. ROI prompt 자체는 후보 provenance에 보존되지만 메인 Recipe에 자동 편입되지 않는다.

## 5. 독립 ROI·수정 후보

- 실제 GUI에서 독립 ROI+양성점으로 후보 1: 51,995px, ROI 절단 경고. 같은 입력 후보 3: 26,405px, 경고 없음. 후보 변경 후 재추론하여 저장했다. 모델 최고 점수만으로 정답을 고르면 안 된다.
- 별도 API 시험은 후보1/3의 미리보기→확정→재로드, 원래 ROI·점·box 저장을 확인했다. 미리보기만으로 프로젝트를 변경하지 않았다.
- 부모 mask 내부 ROI도 실제 SAM 미리보기 28,005px를 생성했다. ROI가 부모에 너무 딱 맞아 절단 경고가 났다. 미리보기 취소 후 저장이 비활성화되고 점 초기화·닫기가 동작했다.
- 기존 mask 수정 SAM은 29,510px 새 후보를 만들었다. 독립 추가 방식으로 layer 배정→해제→취소를 확인했다.
- 브러시 삭제는 원래 29,146px mask를 유지하고 28,021px 새 후보를 만들었다. 새 후보를 취소한 뒤 원래 mask가 유지됐다.
- 모델/장치·후보 점수·ROI 크기·양성/음성·box·사전정렬 등의 조건별 안내가 부족하다. 자동 후보용 NMS/IoU 파라미터를 단일 수동 ROI 추론에 그대로 적용하는 설계는 적절하지 않다.

## 7. 회전·두께·CD 일괄 시험

원래 SAM mask 중 1-cell은 하나, 3-cell은 양끝만 사용했다. 가운데 cell과 나머지 영역은 포함하지 않았다. GT 없이 회전 제안→확정→두께/CD를 실행했다.

| 19 파생 영상 | 아래쪽 기준 보정각 | 중앙60% 두께 평균* | 중앙60% CD 평균* |
|---|---:|---:|---:|
| 1-cell 0° | −0.7689° | 165.82 | 277.21 |
| 1-cell +7° | −8.3796° | 164.42 | 278.45 |
| 3-cell 0° | −0.1029° | 162.93 | 275.97 |
| 3-cell +7° | −6.9205° | 163.19 | 276.63 |
| 3-cell −8° | +7.8533° | 162.92 | 277.11 |

\* nm로 표시된 프로그램 값. 이 fixture의 추가한 100nm/81px 스케일을 사용하는 **시험용 보정값**이며 실제 시료 치수의 정확도 인증이 아니다. 표본 간격 10px, 객체 중앙60%, 같은 객체의 다중 교차 및 프레임 끝점 제외. 단일 mask와 여러 mask의 자동 기준 선택이 달라 보정각도 완전히 같지 않다.

- GUI에서 회전 5/5, 두께 5/5, CD 5/5 완료. 두 축 JSON/CSV를 포함하는 5장 ZIP을 별도로 API로 열어 확인했다.
- 원본/회전 결과 비교 창에서 이미지 두 장이 실제로 로드됐음을 확인했다.
- 기존 ‘전체 구간’ 모드에서는 가장자리의 0에 가까운 짧은 교차가 평균에 들어갔다. 중앙 구간 옵션은 존재하고 효과가 있지만 기본값은 전체 구간이다. 자동으로 진짜 두께를 판단해 주는 기능은 아니다.
- +7° 3-cell의 ‘영상 주 방향’은 약 +83°를 제안했다. 선택 mask 기반 −6.92°와 약 90° 다른 방향이며 경고가 표시됐다. 영상 방향 추정을 물질 수평의 자동 정답으로 쓰면 안 된다.
- 두 대표점의 잔차 0은 수학적으로 당연할 수 있다. 기준이 맞다는 증거가 아니다.
- 회전 재계산 후 이전 CD와 새 두께를 함께 내보내면 만료 오류로 차단됐다. CD를 다시 측정한 후 두 축 출력이 가능했다.

## 8. OCR·스케일

실제 로컬 EasyOCR로 3-cell +7° 영상의 세 영역을 찾았다. scale box `[17,531,104,573]`는 100nm 글씨와 바를 함께 포함했고, magnification `[5,1,69,31]`, footer `[7,582,529,617]`를 제안했다. 추가 일괄 OCR 5장도 실패 0, 모두 제안/검수 필요 상태였다. 개별 OCR·바 제안, 바 검출 81px, 직접 끝점 드래그, 수동 계산, 단일·일괄 확정, 다음 미검수 이동을 시험했다.

검출→제외 적용→스케일 확정은 별도 동작이다. 분석용 주변 채움은 원본 crop이 아니며 유효 영역에서는 제외해야 한다. 이번 영상은 고대비로 추가한 문자이므로 흐린 회사 footer, 회전 문자, 45° 논문 영상의 성공을 새로 입증하지는 않는다. 45° 첨부 영상과 다양한 공개 TEM 재검증은 남은 정확도 시험이다.

이 목록은 반복 행 버튼·동적 확인창·select/checkbox 조합·키보드·드래그까지의 ‘전체 동작 완료율’이 아니다. 실제 image/mask 다중 선택, 표시 토글, 점/box/ROI/brush도 별도 시험했지만 **멀리 떨어진 mask→layer의 native drag, 모든 필터 조합, GPU/학습 bundle, 장시간 대형 batch, 실제 브라우저 다운로드 저장 파일, 보호 brush의 모든 조합**은 완전 검증하지 않았다. 실행 버튼이 모두 정상이라고 보고하지 않는다.

기존 회귀 증거는 별도 [기능 보존 감사](FEATURE_PARITY_AND_DEMO_KO.md)에 있다: Python 169개, Node 6스위트 통과. 이번에는 생산 코드를 바꾸지 않았고 실제 모델/API/GUI 시험을 추가했다. 일부 회귀시험은 mock을 쓰므로 모델 정확도 증거로 계산하지 않는다.
